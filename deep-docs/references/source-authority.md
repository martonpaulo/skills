# Source authority

Prefer, in order:

1. official versioned documentation;
2. official specifications and API schemas;
3. official release and migration notes;
4. official source repository documentation;
5. local installed CLI documentation;
6. accepted standards or language proposals;
7. official vendor forums;
8. community sources.

Local CLI output is authoritative for what is installed, not necessarily for other releases. Repository documentation must belong to the official project organization or vendor before it is labeled primary. Community sources may identify terminology, missing coverage, or risks, but consequential claims should be verified through a primary source.

Always retain a source URL, repository reference, specification URL, or `cli://` identifier. Record source and publication/update versions when available. If version identity is unresolved, say so.
