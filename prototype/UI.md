# UI and Interaction Experiments

Use this shape when the uncertainty concerns layout, information hierarchy, interaction, accessibility behavior, or platform conventions.

Build only enough of the surface to evaluate the stated question. Reuse established components and tokens when they can be imported without modifying production code. Use representative sample data and include the states needed for the question, such as empty, loading, error, selected, keyboard focus, or narrow layout.

Create multiple variants only when comparing materially different approaches is part of the question. Variants should differ in structure or behavior, not merely color or copy.

Keep actions local and reversible. Stub mutations and remote calls unless they are the subject of the experiment. Provide one clear run or preview command, then report the observed result and the disposable files.
